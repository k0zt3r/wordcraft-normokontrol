# Работа агента с нормоконтролем

Для обработки документов используй агентный интерфейс, описанный в
[references/agent-interface.md](references/agent-interface.md). Он вызывает тот же
обработчик, что GUI и обычная командная строка. Не управляй GUI для пакетной обработки.

## Порядок работы

1. Выполни `python normokontrol.py --agent get_capabilities`, затем
   `python normokontrol.py --agent doctor`. Проверь `data.ready` и диагностику.
2. Для первоначальной проверки вызови `check_document` с абсолютным `input`.
   Для воспроизводимости передавай отдельную папку `out` для каждого запуска.
3. Если пользователь поручил оформление, вызови `format_document` с `input`, новой
   папкой `out` и известными реквизитами в `metadata`. Для заготовки используй
   `create_document` с `out`. Не подставляй вымышленные данные.
4. Разбери `data.report.issues` и `data.issue_counts`; при необходимости вызови
   `get_report` с фильтром `severity` или `code`. Основание замечания проверяй через
   `get_requirement` и локальный источник требований.
5. Передай пользователю пути из `data.artifacts`, сведения об оставшихся замечаниях
   и необходимости ручной проверки. Не объявляй работу соответствующей всем
   требованиям только на основании успешного выполнения.

## Интерпретация результата

- `ok: true` означает, что операция выполнена. `status: completed_with_findings`
  означает, что остались замечания; это не технический сбой.
- `ok: false`, `status: error` — ошибка операции. Прочитай объект `error` перед
  повторным запуском. Не повторяй обработку в той же папке результатов.
- `doctor` может завершиться с `ok: true`, но `data.ready: false`: диагностика
  выполнена, окружение ещё не готово к обработке.
- Агентный CLI возвращает `0` для выполненной операции, включая замечания, `1` —
  для ошибки. У обычного CLI сохраняются коды `0`, `2` (замечания), `1` (ошибка).

## Ограничения и источники

Исходник не изменяется. Даже `check_document` экспортирует копию DOCX через
Wordcraft и PDF для проверки вёрстки; копия не обязана побайтно совпадать с исходником.
Для каждого оформления выбирай новую папку. Файлы предыдущих запусков не перезаписываются.

Первичен [Normokontrol.pdf](Normokontrol.pdf). Машиночитаемые основания:
[реестр требований](references/norm-source/requirements.json),
[индекс пунктов](references/norm-source/clauses.json) и
[полный текст](references/norm-source/full-text.md). Исторические обзоры и старые
пользовательские настройки не отменяют положение. Отличай обязательную норму,
рекомендацию, условное требование и технический выбор программы.

Не придумывай подписантов, кафедральные номера, библиографические сведения или
содержание работы. Автоматическая проверка не подтверждает смысл текста, полноту
разделов, достоверность источников и совпадение вёрстки с Microsoft Word.

## Разработка

Общий контракт находится в `scripts/agent_api.py`, транспорт MCP — в
`scripts/agent_mcp.py`. Сохраняй чистый JSON в stdout агентного CLI и MCP; сообщения
прогресса и диагностику направляй в stderr. MCP обрабатывает вызовы последовательно;
асинхронные задания и отмена через протокол не предоставляются.

Проверки: `python -m unittest discover -s scripts -p "test_*.py"`.
Интеграционным тестам нужен установленный Wordcraft, GUI-тестам — рабочие Tcl/Tk
и пользовательская сессия Windows. При изменении состава поставки учитывай список
обязательных файлов и разрешённых путей обновления/восстановления.
