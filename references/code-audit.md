# Итоговый аудит кода, 02.11.2026

Версия: 1.3.2. Проверены обработка DOCX через Wordcraft, структурные проверки, построение отчёта, запуск GUI/CLI и упаковка обновления. Цель — убрать подтверждённую лишнюю работу и ошибки без изменения требований оформления.

1. **Поиск автооглавления больше не сканирует обычный текст посимвольно.** Полный разбор выполняется только при наличии полей или внутри уже открытого TOC. Сохранено распознавание полей через несколько абзацев, вложенных полей и незакрытого TOC.
2. **Проверка связи названия таблицы с её началом больше не измеряет последнюю строку.** Деление таблицы между строками разрешено положением. Для определения начала по-прежнему учитываются все ячейки первой строки, включая вложенные абзацы. Повторная проверка после сохранения DOCX сохранена.
3. **Убраны повторные вычисления границы титульника и ненужный начальный расчёт страниц в режиме проверки.** Граница не меняется от переименования заголовков и рассчитывается один раз в соответствующем проходе.
4. **Облегчено построение отчёта.** Текст приложений берётся из полного Markdown, а не из большого JSON с координатами и шрифтами. Индекс пунктов строится однократно за отчёт, ссылки для каждого изменения вычисляются без дублирования. Полный Markdown включён в обязательные файлы обновления.
5. **Удалены пять неиспользуемых импортов и устаревший обход последних строк таблиц.** Подтверждённых мёртвых модулей или функций при проверке вызовов не найдено. Тесты и инструменты корпусных прогонов сохранены как средства воспроизведения ошибок.
6. **Исправлена обработка структурных заголовков с автоматической нумерацией.** «Введение», «Заключение» и заголовок источников не получают номер из списка. При переименовании источников используются позиции в текущем тексте; лишний хвост старого названия не остаётся.
7. **Убрана незаявленная зависимость теста от Pillow.** Тестовое изображение создаётся средствами уже используемого PyMuPDF. Новых зависимостей приложения нет.
8. **Документация очищена от смешения текущих инструкций с историей.** Старые изменения перенесены из раздела устранения ошибок README в [историю версий](changelog.md). Исторические обзоры не являются действующими правилами; источник требований — [положение и его извлечение](norm-source/README.md).
9. **Исправлено создание пустой заготовки без содержания.** После удаления пустого основного текста граница титула могла теряться: таблица подписей принималась за обычную таблицу, а проверка требовала несуществующее начало работы на второй странице. Последняя граница раздела учитывается, титул не форматируется как основной текст, наличие второй страницы проверяется только при наличии содержательного основного блока.

## Замеры

Один контрольный документ на 39 страницах, одна машина, три чередующихся запуска каждой версии через отдельные процессы Python и Wordcraft. Для сравнения использована изолированная копия 1.3.1 из Git. Время измерялось без профилировщика, от входа в обработку до выдачи результата; импорт Python-модулей не включён.

| Показатель | 1.3.1 | 1.3.2 |
|---|---:|---:|
| Время трёх запусков, с | 2,8157 / 2,7355 / 2,7361 | 2,4805 / 2,4991 / 2,5909 |
| Медиана, с | 2,7361 | 2,4991 |
| Запросы `document.layout` за обработку | 276 | 202 |
| Страницы результата | 39 | 39 |
| Замечания в контрольном результате | 2 | 2 |

Локальное сокращение медианы времени — около 8,7%; запросов вёрстки — около 26,8%. Это измерение на одном документе, а не обещание такого ускорения для каждого DOCX. Замеры под профилировщиком отдельно использованы для поиска узких мест, но не для оценки пользовательского ускорения.

При сравнении результатов совпали тексты всех 39 страниц, координаты текстовых фрагментов с точностью 0,01 пт и контрольные суммы изображений. Исходный документ не перезаписывался.

## Объём и проверка

На начало аудита в Git: 105 файлов, около 12,2 МБ. Около 10,1 МБ занимают извлечённое положение, координаты и оригинальные рисунки. Эти данные сохранены по запросу пользователя и не являются случайными копиями. Локальные результаты прогонов хранятся в игнорируемом `outputs/`, в Git не попадают; контрольные копии этого аудита удаляются после сравнения, метрики сохраняются отдельно.

Регрессионные проверки проходят, включая реальный цикл сохранения и повторного открытия через Wordcraft, автоматическое и ручное содержание, картинки в ячейках, защиту текста и восстановление обновления. Дополнительно проверяется установка полного ZIP и запуск установленного CLI.

Остаётся практическое ограничение: программа использует признаки структуры DOCX и не доказывает смысловую принадлежность любого произвольного абзаца главе. Неоднозначные документы, подписи, реквизиты и содержание требуют просмотра отчёта. Массовая смена эвристик распознавания и переразбиение большого основного модуля в этот аудит не включены: это отдельные изменения поведения, а не очистка мусора.
