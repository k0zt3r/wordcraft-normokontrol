# Прямой интерфейс для агентов

Агентный CLI, Python API и MCP используют общий контракт и существующий механизм
оформления. GUI для этих вызовов не запускается. Установщик поставляет приватный
Python с зависимостями и при необходимости скачивает Wordcraft; при ручном запуске
из ZIP Wordcraft устанавливается отдельно. Открывать окно редактора не требуется.
В установочной версии используйте `runtime/python.exe` вместо системного `python`.
Базовый шрифт штампа — Times New Roman, 9/16 пт; ISOCPEUR не обязателен.

## Быстрый старт через JSON

Из корня проекта:

```powershell
python normokontrol.py --agent get_capabilities
python normokontrol.py --agent doctor
python normokontrol.py --agent check_document --request check.json
```

`check.json` — UTF-8 JSON с аргументами операции:

```json
{
  "input": "C:/Works/course.docx",
  "out": "C:/Works/results/check-001",
  "mode": "full"
}
```

Для оформления создай `format.json` и выполни
`python normokontrol.py --agent format_document --request format.json`:

```json
{
  "input": "C:/Works/course.docx",
  "out": "C:/Works/results/format-001",
  "metadata": {
    "author": "И.И. Иванов",
    "group": "БИС-22-1",
    "title": "Тема работы"
  }
}
```

Данные выше демонстрационные: передавай только известные реквизиты пользователя.
Аргументы можно передать через stdin: `--request -`. Без `--request` используется
пустой объект `{}`. stdout содержит один JSON-ответ; прогресс выводится в stderr.
При использовании из другой папки укажи абсолютный путь к `normokontrol.py`.
Относительные пути аргументов считаются от текущего рабочего каталога процесса.

## Операции

Точные схемы аргументов возвращает `get_capabilities`; MCP также публикует их
через `tools/list`. Неизвестные параметры и неверные типы отклоняются.

| Операция | Аргументы и результат |
|---|---|
| `get_capabilities` | Без аргументов: возможности, схемы, ограничения и порядок работы |
| `doctor` | Необязательный `wordcraft`: явный путь к CLI. Возвращает диагностику и `ready` |
| `check_document` | Обязательный `input`; необязательные `out`, `mode`, `wordcraft`. Проверяет без автоматических исправлений |
| `format_document` | Обязательные `input`, `out`; параметры оформления и реквизиты ниже |
| `create_document` | Обязательный `out`; те же параметры оформления, без `input`. Создаёт заготовку |
| `get_report` | Обязательный `path`: `report.json` или папка результата. Фильтры `severity` (`error`, `warning`, `review`) и `code` |
| `get_requirement` | `reference`: точное обозначение, например `6.2`; `search`: поиск по тексту. Получает основания из локального источника |

Для оформления и создания доступны `mode` (`full` по умолчанию или `compact`),
`wordcraft`, `format_text`, `metadata`, `toc_template`, `bibliography_template`,
массивы строк `toc_entries`, `bibliography_entries` и `optional_sections`
(`annotation`, `normative`, `abbreviations`). `full` предназначен для полного
нормоконтроля с рамками и штампами, `compact` — для обычной учебной работы.
`format_text: false` сохраняет оформление текста, но разрешает остальные
преобразования выбранного режима, включая исправление переносов и содержания.

Пустые реквизиты сохраняют исходные значения. Неполные библиографические сведения
и содержательные разделы программа не дописывает. Созданная заготовка не считается
завершённой учебной работой.

## Контракт ответа

Все операции возвращают объект с полями `schema_version`, `ok`, `status`, `data`,
`error`. Версия контракта — `1`.

- `completed`: операция выполнена.
- `completed_with_findings`: обработка выполнена, остались замечания.
- `error`: операция не выполнена; подробности находятся в `error`.

Успешная обработка документа возвращает в `data` абсолютные пути `artifacts`,
сводку `issue_counts` и полный `report`. Замечания в отчёте содержат `code`,
`severity`, `message`, `page`; номер страницы может отсутствовать. Значение
`automated_only: true` и отсутствие проверки в Microsoft Word сохраняются в отчёте.

Успех `doctor` означает выполнение диагностики. Перед обработкой отдельно проверь
`data.ready`: при значении `false` устрани причины из диагностического ответа.
Код завершения агентного CLI — `0` при `ok: true`, включая оставшиеся замечания,
и `1` при ошибке. Обычный CLI сохраняет прежние коды `0`, `2`, `1`.

У `get_report` фильтры применяются к `data.issues`; `matched_issues` — число
совпадений, `total_issues` — общее число. Поля `data.report` и `issue_counts`
содержат полный исходный отчёт и общие количества, независимо от фильтра.

`get_requirement` сверяет SHA-256 текущего PDF с реестром. Если источник изменён,
операция возвращает ошибку до выдачи требований.

## Подключение через MCP

Запуск сервера: `python normokontrol.py --mcp`. Транспорт — stdio; stdout занят
протоколом. Пример конфигурации для клиента с секцией `mcpServers`:

```json
{
  "mcpServers": {
    "wordcraft-normokontrol": {
      "command": "C:/Python312/python.exe",
      "args": ["C:/Projects/wordcraft-normokontrol/normokontrol.py", "--mcp"]
    }
  }
}
```

Замени оба пути абсолютными путями своего компьютера. Формат конфигурации зависит
от MCP-клиента; этот пример не означает, что подключение уже установлено.
Сервер предоставляет перечисленные операции как инструменты. Вызовы выполняются
последовательно; фоновые задания и отмена через MCP не поддерживаются. Для больших
документов настрой достаточный тайм-аут вызова в клиенте.

## Python API

Из корня проекта:

```python
from scripts.agent_api import invoke

diagnostics = invoke("doctor", {})
if not diagnostics["ok"] or not diagnostics["data"]["ready"]:
    raise RuntimeError(diagnostics)
result = invoke("check_document", {
    "input": "C:/Works/course.docx",
    "out": "C:/Works/results/check-002",
})
if result["ok"]:
    print(result["data"]["artifacts"])
else:
    print(result["error"])
```

## Сохранность и проверка результата

Исходный документ не изменяется; результаты прошлых запусков не перезаписываются.
Для повторного запуска выбирай новую папку. `check_document` не применяет
автоисправления, но сохраняет проверяемую копию DOCX через Wordcraft и создаёт PDF:
это не обещание побайтной идентичности исходнику. DOC со старым форматом и DOCX
с отслеживаемыми исправлениями требуют подготовки отдельной совместимой копии.

Рекомендуемый цикл: `get_capabilities` → `doctor` → `check_document` →
`format_document` (если поручено оформление) → разбор отчёта и ручной просмотр.
При `completed_with_findings` изучи замечания, прежде чем повторять обработку:
содержательные вопросы и неоднозначная структура не устраняются повторным запуском.

Первичный источник — [Normokontrol.pdf](../Normokontrol.pdf), а
[реестр](norm-source/requirements.json) различает обязательные нормы, рекомендации
и требования, зависящие от контекста. Индекс пунктов включает вхождения из
оглавления и примеров; учитывай контекст страницы. Исторические обзоры проекта не
заменяют действующий источник. Автоматический отчёт не подтверждает смысл работы,
достоверность источников или идентичность вёрстки Microsoft Word.
